# --- needed for the agent, near the end of the build ---

groq==1.7.0
# The agent that decides what to investigate and explains the forecast.
# It never does arithmetic -- a guardrail checks every number in its answer
# against the tool output it was given, and rejects the answer if a number
# appears that the tools never produced.
#
# Groq is used on its free tier. The model is reached through a thin seam so
# the provider is a one-file change: the agent is developed against a stub
# that returns canned tool calls, which is also the only way to have tests for
# it -- tests that hit a live API are tests you stop running.

python-dotenv==1.2.3
# Reads GROQ_API_KEY out of a local .env file, which is gitignored.
# Never put the key in code.


# --- deliberately not used ---
#
# pandas       Not needed. The whole dataset is ~1,200 sales and ~854 forecasts,
#              which plain Python handles without help. More importantly, every
#              amount here is an integer number of paise, and a single missing
#              value in a pandas int column silently promotes the whole column
#              to float64 -- which is exactly the class of bug this project
#              claims to avoid. Averages and percentiles come from the stdlib
#              `statistics` module.
#
# numpy        Same reason. Nothing here needs arrays.
#
# scikit-learn No model is trained. The forecast is averages, ratios and
#              percentiles computed fresh from history each time.
#
# matplotlib   The report is a table. Add it only if a chart is wanted for the
#              demo, and note that it is presentation, not measurement.
